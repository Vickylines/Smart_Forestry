**后端接口约定 v0.1 · 待实现**

本文件定义下一阶段客户端与后台的约定，当前还没有相应服务器。建议统一前缀/api/v1，使用HTTPS和JSON；由后台转发植物识别请求，客户端不接触供应商密钥。

**实体关系**

Project关联成员与Observation；一条Observation表示某次植物观察，可关联多张Photo。RecognitionJob通过JobItem处理照片或观察，保存Candidate列表；Review保存人工决定和历史。植物个体编号应独立于观察编号，后续支持跨日期复查。

**接口清单**

| 方法与路径 | 输入或用途 | 关键行为 |
|---|---|---|
| GET /health | 服务可用性 | 不返回密钥等配置 |
| POST /auth/session | 登录凭据或平台授权码 | 仅由服务器换取令牌 |
| GET /projects | 查询有权限的项目 | 分页、成员权限隔离 |
| POST /projects | client_id、name、location | client_id与主体联合幂等 |
| POST /projects/{id}/observations | client_id、采集时间、备注、个体关联 | 明确示例标志，支持无位置 |
| POST /photos/uploads | observation_id、文件名、大小、MIME、校验和 | 校验权限后创建上传凭据 |
| POST /photos/{id}/complete | 上传确认 | 服务端校验实际文件，不相信客户端成功标志 |
| POST /recognition-jobs | project_id、observation_ids、策略 | 已上传文件才可入队；返回202和job_id |
| GET /recognition-jobs/{id} | 任务进度 | 成功、失败、待处理、取消分别计数 |
| POST /recognition-jobs/{id}/cancel | 取消未开始项 | 已发出的供应商请求不承诺撤销收费 |
| POST /recognition-jobs/{id}/retry | 指定可重试失败项 | 不重跑已成功项，计费语义明确 |
| GET /observations/{id} | 照片、候选、最终鉴定 | 返回revision、临时媒体访问地址 |
| PATCH /observations/{id}/review | expected_revision、decision、taxon、note | 冲突返回409；记录操作者与时间 |
| POST /projects/{id}/exports | 状态筛选、是否含图片、格式 | 长任务返回202；导出快照可追溯 |

写操作采用Idempotency-Key，同一身份和同一接口内相同键且相同请求体返回原结果；键相同但请求体不同返回409。不声称外部服务一定支持幂等，遇到供应商响应丢失仍需记录潜在重复计费。

**上传与识别状态必须分开**

客户端上传状态：local_only → uploading → uploaded；失败进入upload_failed，用户可恢复。

服务端识别状态：queued → running → succeeded / failed / cancelled。succeeded只代表接口处理成功，物种仍可为unknown；网络失败、鉴权失败和配额不足不能写为unknown。

审核状态：pending / confirmed / undetermined。人工修改不覆盖候选原文和服务调用信息。

队列按账户额度限速，临时失败进行有上限的指数退避，格式和鉴权错误不盲目重试。任务记录持久化，Worker使用租约与幂等回写；进程重启后能恢复。任务不放在一次HTTP请求的内存生命周期里。

**候选响应约定**

```json
{
  "observation_id": "obs-client-generated-id",
  "revision": 1,
  "is_demo": false,
  "recognition_status": "succeeded",
  "review_status": "pending",
  "provider": "configured-provider",
  "provider_model_version": null,
  "recognized_at": "2026-09-06T08:00:00Z",
  "candidates": [
    {
      "rank": 1,
      "provider_name": "供应商原始名称",
      "taxon_id": null,
      "scientific_name": null,
      "raw_score": 0.87,
      "score_is_calibrated_probability": false
    }
  ]
}
```

上例字段和值仅说明结构，不是真实识别结果。供应商未提供模型版本则为null；学名无法可靠映射也保留null，不能生成一个看似规范的名称填补缺失。

**存储与测试要求**

数据库保存身份、项目、任务、候选和审核历史；照片使用私有对象存储，访问使用短期凭据。服务日志屏蔽供应商密钥、访问令牌和图片内容。发布前至少验证权限隔离、上传校验、重试幂等、服务重启恢复、revision冲突、无图像结果与费用上限。

定位功能后续增加longitude、latitude、coordinate_system、accuracy_m和source字段，采集坐标与展示坐标分开。正式上线前依据实际平台和数据用途确定保留、导出和删除行为。
