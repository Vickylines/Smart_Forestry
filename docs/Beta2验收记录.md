# Beta 2 故障修复验收

日期：2026-09-07（Asia/Taipei）。版本：0.3.0-beta.2，Android versionCode 31。

## 复现与修复

| 问题 | 证据与修复 |
| --- | --- |
| 已有资料在启动写入失败时显示为空 | 在启动前拦截状态写入并抛出 QuotaExceededError，旧版显示 0 个项目。修复后跳过无变化的写入；迁移写入失败仍保留已读资料并允许导出。 |
| 采集照片在重启后丢失；临时文件提前删除导致无法重试 | 旧版双照片恢复用例在刷新后丢失第一张。原生新建选择器与每张照片持久化均会提前清理临时文件。现将照片与草稿引用持久保存后才按 URI 确认清理，提交观察与移除草稿在一次状态写入中完成。 |
| 密钥验证只使用缓存令牌 | 原生鉴权测试先返回成功，再模拟同一密钥失效，要求第二次验证再次访问 OAuth 并返回错误。普通照片请求仍可复用有效令牌；失败后能重试。 |
| 读取故障被当成首次安装 | H5 的 uni.getStorageSync 会吞掉读取异常。改为直接读取 localStorage 并兼容旧包装格式；真实读取失败时阻止修改。 |
| 未处理的拍摄照片属于另一项目 | 故障回归保留项目 A 的照片并进入项目 B；点击拍照后可返回 A 处理，不改变归属。 |

同时调整了原生请求锁在回调前释放，以及前端超时从 65 秒到 90 秒。首次识别可能依次经历 OAuth 与识别请求，原来的前端等待短于两阶段连接和读取超时之和。此项为代码检查所得；没有模拟真实移动网络的全部延迟组合。

## 检查记录

- `npm run type-check`。
- `npm test`：14 项领域测试，包含草稿提交的原子性、重复保存拦截和项目删除。
- `npm run test:regressions`：5 组，覆盖启动写入、迁移写入、读取失败、照片草稿恢复与重试、跨项目待处理照片；删除项目后照片数据库无遗留草稿。
- `npm run test:browser`：项目、采集、复核、设置入口、导出、删除和小屏／大字布局。
- `npm run test:integration`：模拟百度结果、部分失败与继续识别、原图 ZIP、密钥 UI。
- 独立 `.qa` APK 的 `BaiduRegression`：使用模拟 HTTPS，不消耗额度；重新验证、密钥失效、重试、照片请求缓存、鉴权 POST 参数与移除凭据均通过。
- Pixel 4 XL / Android 16：连续两张相机照片；取消第三次拍摄不丢失已有照片；强制停止并重启后照片、备注和分组保留；模拟记录写入失败后再次保存成功；保存前后两张照片的 SHA-256 均不变，无重复草稿。
- H5、微信小程序和 app-plus 资源均编译通过；后两项仅代表资源编译，不代表相应平台真机验收。
- 发布 APK 签名验证与归档检查通过，未包含测试类、测试密钥、私钥文件或源码映射。版本为 0.3.0-beta.2 / 31；应用调试、备份和明文网络均关闭。
- 发布包在现有主应用上覆盖安装并冷启动成功，`run-as` 返回不可调试；未清除主应用数据。

原生照片与原始测试报告仅在本地 `.preview/bugfix/`，不上传仓库或发布页。测试使用独立 QA 包，不读取已安装主应用的资料或密钥。

## 范围

照片草稿只保存在本机，重新进入同一项目的“添加观察”即可继续。CSV/ZIP 导出仍针对已保存观察，备份前请提交草稿。现有数据与 Beta 1 签名保持兼容。

本轮未使用有效生产密钥调用百度植物识别。原生模拟鉴权证明的是应用逻辑，不能代替真实识别权限、额度与准确率测试。

本轮未升级依赖版本；[Beta 1 记录](Beta1验收记录.md)中的开发工具链审计告警没有因此解决。APK 不内置开发服务器，测试类和测试凭据仅存在于隔离 Inspection 包中。
