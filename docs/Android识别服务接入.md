# Android 识别服务接入

当前 Android 已支持手机直连百度，凭据已完成验证，无需部署电脑后台。见 [百度直连验收](./Android百度直连验收.md)。本文保留可选后台接入方案；自动化模拟响应不代表真实识别准确率。

## 用户操作

1. 新建项目，拍照或从相册选择照片，填写备注并保存。
2. 同一株植物的照片可以合并为一条观察；每次最多 9 张，每张最多 20MB。
3. 保存后进入任务列表。没有服务时显示“连接识别服务”，不会产生假的候选名称。
4. 查看观察记录，可直接填写或修改植物名称、学名和备注，保存复核。
5. 项目底部“导出照片和表格”生成 ZIP，选择手机目录保存。解压后有照片、观察表、照片清单和复核历史，可传到电脑使用。现有 EXE 尚未实现自动导入协议，CSV 可以先用 Excel 打开。

## 后台接入约定 v1

这是一组供单设备识别使用的精简接口，不要求实现原规划中的完整登录和云同步。应用设置填写 HTTPS 基础地址（例如 `https://example.org/forest`）及后台访问口令。访问口令不是百度 API Key 或 Secret Key。凭据只保存在本机设置，不进入导出的资料包。

应用仅访问所填地址的 `/health` 与 `/recognize`，不跟随重定向。后台应允许来自 `https://appassets.androidplatform.net` 的 CORS 请求，包含 GET、POST、OPTIONS 和 Content-Type、Authorization 请求头；预检 OPTIONS 不要求携带令牌。正式接口必须校验访问口令、限制上传大小及调用频率，不能成为公开的无认证转发代理。

### GET /health

请求头可含 `Authorization: Bearer <后台访问口令>`。

```json
{"service":"forest-recognition","apiVersion":1,"ready":true}
```

后台供应商凭据未配置时，返回 `ready:false`。客户端只显示连接成功，不会把健康检查当作图片识别。

### POST /recognize

请求头 `Content-Type: application/json`；认证头同上。

```json
{"requestId":"job-id:photo-id","image":"不含data前缀的JPEG Base64"}
```

客户端保留保存照片，对上传副本缩放至最长边不超过 1600 像素，编码长度最多 4MiB。后台仍须独立校验大小和图片有效性。按百度当前接口文档实现 token 获取、单图请求和名称评分解析；不能假定返回学名与科属，未知字段留空。

成功返回示例（下列值仅说明字段，不是真实结果）：

```json
{"provider":"baidu-plant","candidates":[{"name":"候选中文名","scientificName":"","score":0.8}]}
```

`candidates` 可以为空；最多 20 项，每项名称非空，score 必须是 0 到 1 的有限数值。HTTP 401/403 表示凭据或权限问题，429 表示限流或额度不足，503 表示服务不可用。响应与日志不能包含供应商密钥。

客户端按照片逐张执行，每次成功后立即保存；同株照片候选按名称去重，取最高原始评分，最多展示 5 项，并保留各张照片的原始候选、服务名和时间。候选变化不覆盖人工名称和复核记录。

后台应按 `requestId` 和请求内容提供持久幂等缓存；同 ID 不同内容返回 409。客户端不会自动重试失败调用，由用户点“继续识别”。照片成功但响应丢失时再次提交可能产生重复费用，必须依靠后台幂等处理，而不能声称客户端能保证供应商仅计费一次。

## 暂停与限制

- 识别时保持应用打开；转入后台或手动暂停后，不再发起下一张请求，当前已发送请求可能继续完成。重新打开后可继续，跳过已保存成功的照片。
- 本版没有离线识别模型、云同步或正式账号系统，也不保证应用被系统回收后继续识别。
- ZIP 导出照片总量上限 190MB，文件包上限 200MB，超过时提示拆分项目。未实现从 ZIP 恢复到手机；它用于电脑归档与后续 EXE 接入。
- 当前 APK 为沿用原包名和本机测试签名的测试包，可覆盖安装并保留数据；启用了 WebView 调试供验证，商店发布前应关闭并配置正式签名。
